## Decision Summary

### Chosen Approach
**One role store + original parametric SVG clay system + event-driven walker + D1 counters with polling.** One new store (`thao:visitor:v1`) is the single source: role, collapsed, guideHidden, visitorId, ordinal. Avatars are hand-written layered SVG (radial gradients, no filters). Walker is a fixed transform-only node fed by cached rects (refreshed on scroll/resize/ResizeObserver, not per frame). Stats are `VisitorSeen` + `VisitTally` + `PollVote` in D1, polled.

### Why This Over Alternatives
| Alternative | Why Rejected |
|---|---|
| Licensed clay/3D packs (Fluent Emoji etc.) | Not original (hard requirement), style drift, terms unverified |
| Rive/Lottie avatars | New runtime + external authoring toolchain, bundle risk |
| Pre-rendered sprite PNGs | Heavy bytes, cannot recolour for skin/hair, needs 3D toolchain |
| Durable Object / SSE push for stats | Needs custom Worker entrypoint, repo has none; vanity data does not justify it |
| Reuse `participate` store + `PERSONAS` | `PERSONAS` is lab-only and includes "curious" with different semantics; collision across 11 roles. New store, one-time migration from `thao:participate:persona` |
| Copy flowser mascot code | Private repo, no LICENSE, ownership unproven; also needs sonner/next-image. Reimplement technique only |
| Per-frame `getBoundingClientRect` scan (flowser style) | Forces layout every frame; cache rects, update on events |

### Risk Predictions (vc-predict, 5 personas)
- **Architect:** two stores risk drift. Mitigation: legacy persona read exactly once at store init; lab code untouched. `roles.ts` is the single content table (label, order, note, guide lines, avatar spec) and a unit test enforces completeness.
- **Security/privacy:** vanity counters invite inflation; salted hash needs a real `VISITOR_SALT` secret (fail closed 503 if unset in production); Origin/Host check, 512-byte body cap, enum-only inputs, per-hash write throttle; country only from `cf`. E2E geo header seam must be inert on Cloudflare (guard on local DB source + `PORTFOLIO_E2E=1`).
- **Performance:** walker rAF only moves a transform; rect reads on events only; lazy-mount after first paint; avatar SVG per-instance gradient ids via `useId`; people section renders up to N avatars so avatars must stay under ~6 KB each.
- **UX/design:** R4 dropped poll/characters/greeting as busy and fake-looking. Reversal accepted by Thao; guard rails are ACs: <= 6 guide lines, hide persists, percentages gated, no fake baselines, guide never overlaps nav pill/tap targets.
- **QA:** persona e2e tests (`home.spec.ts` "Show me first:") and `home-redesign.test.ts` persona tests will break by design; P3 owns updating them. Autoresearch loop concurrently edits home files; lane gating below.

## Public Contracts
- localStorage `thao:visitor:v1` = `{ v:1, role: RoleId|null, collapsed: boolean, guideHidden: boolean, visitorId: string, ordinal: number|null }`. Legacy `thao:participate:persona` read once to seed `role` when it is recruiter/founder/engineer.
- `RoleId = "recruiter"|"founder"|"engineer"|"designer"|"marketer"|"growth"|"data"|"investor"|"student"|"pm"|"curious"`; `null` = skip.
- `GET /api/geo` -> `{ country: "VN"|null, city: string|null }` (`Cache-Control: no-store`).
- `POST /api/visit` body `{ visitorId: string(8-64 [A-Za-z0-9_-]), role: RoleId|null }` (zod `.strict()`: extra keys such as a client-sent country are 400) -> `{ ordinal: number, counted: boolean }`; 400 invalid or extra keys, 403 bad or missing Origin, 413 big body (Content-Length precheck plus bounded 512 B read), 429 throttled (with `Retry-After`), 503 no salt or salt shorter than 16 chars in production. The server writes only on first choice or an actual role change; an unchanged role is a no-op returning `counted:false`.
- `GET /api/stats?role=<RoleId|none>` -> `{ total, byRole: Record<RoleId,number>, topCountries: {country,count}[], you: { country, countryCount, countryRank, roleCount } }`, `Cache-Control: private, max-age=10`. The aggregate part (total, byRole, topCountries LIMIT 5) is derived from ONE `SELECT` over `VisitTally` and memoised at module level for 10 s (injected clock); only `you` is computed per request.
- `POST /api/poll` body `{ visitorId, option: PollOptionId|null }` (`null` = read only, no write; `.strict()`) -> `{ counts, total, mine }`. No visitor id ever appears in a URL or query string: there is no `GET /api/poll?visitorId=`; an anonymous `GET /api/poll` returns `{ counts, total }` only. A vote requires an existing `VisitorSeen` hash and reuses the write throttle (429 + `Retry-After`). Percentages are computed client-side only when `total >= MIN_POLL_VOTES (20)`.
- D1 tables (S1, S4): `VisitorSeen(hash PK, role TEXT NOT NULL DEFAULT 'none', country TEXT NOT NULL DEFAULT 'XX', changeCount INTEGER, firstSeenDay TEXT, updatedDay TEXT, lastWriteAt INTEGER)`, `VisitTally(role TEXT NOT NULL DEFAULT 'none', country TEXT NOT NULL DEFAULT 'XX', count INTEGER, PK(role,country))`, `PollVote(hash PK, option, updatedDay TEXT)`. Sentinels (`'none'`, `'XX'`) replace NULL so the composite key and `ON CONFLICT` work. `country` is written once at first insert and never updated. Timestamps are UTC-day (`YYYY-MM-DD`); the only finer field is `lastWriteAt` (epoch ms, overwritten on each write, used solely for the throttle). Visitor ordinal = implicit `rowid` of `VisitorSeen`. Tallies are derivable from `VisitorSeen` (`rebuildTallies`).
- Hash: `HMAC-SHA256(VISITOR_SALT, visitorId)` hex; the id and the hash are never logged.
- Component contracts: `ClayAvatar({ role, skin?, hair?, pose?, size, title? })`; `useVisitor()` -> `{ role, setRole, collapsed, setCollapsed, guideHidden, setGuideHidden, ready, ordinal }`.
- Env: `VISITOR_SALT` (secret, required in production, at least 16 chars else treated as unset), `PORTFOLIO_E2E=1` enables the `x-e2e-geo` header seam (inert unless DB source is local; env and DB source are injectable parameters of `readGeo`).
